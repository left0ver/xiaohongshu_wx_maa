# 微信视频号插件

当前 0.8.0 后续修订（2026-11-06）：第一批同策略三个视频的完整应用内采集通过，平均 245.985 秒。修复单字评论昵称导致文案混入、头像旁认证混入简介、基础信息 ID 标签模板误拒绝；5 秒就绪预算不变。昵称和文案按首次结果保存，不再返回复核，仍有昵称错字、标点及装饰表情 OCR 差异，不宣称逐字准确。第二批仍为默认关闭的可见一级评论初版，翻页、二级回复及上报未完成。详细证据和每阶段耗时见 [第一批验收](../../docs/wechat-batch1.md)。下方旧版本记录不代表当前验收结论。

PI v2 入口：`wechat_channels/interface.json`。共享识别与动作节点：`wechat_channels/resource/base/pipeline/channels.json`。

可组合操作：打开微信、进入发现、打开视频号、打开当前视频作者主页、打开主页中的视频、点赞当前视频、返回作者主页、返回推荐页、进入视频号个人页。点赞先识别状态，已点赞则跳过；点击后必须确认状态，不盲目重试。

「点赞并访问」组合和独立点赞操作都定位白色拇指图标后点击一次，在相同识别位置验证红色状态；不使用固定视频区域坐标，不因校验失败反复点击。已点赞则跳过点赞动作。

稳定导航文字优先使用多尺度模板，未命中再通过宿主 `MtaOcrFallback` 执行 OCR。新增操作需要同时修改 pipeline、interface、两份 locale 和相应逻辑测试。

原组合 0.3.0 的 60 秒目标尚未完成真机验收。历史 0.2.6 完整流程记录约为 vivo 102.4 秒、TINA 119.3 秒，不能当作当前版本的性能保证。

0.4.0 新增「采集当前视频（第一批）」任务，默认只勾选采集任务，原有组合与预设保留。采集通过 `collector/main.py` 注册的 `CollectWechatVideo` 执行，读取作品和作者资料，返回确认原作品后才写入 SQLite；不执行点赞、不上传服务端。

0.5.0 参考小红书的语义控件方式：优先读取最新控件树，字段不完整才回退；发现、视频号、推荐导航复用已有的多尺度模板及页面组合校验，模板未命中才 OCR。控件或模板目标在点击前重新识别，唯一性或位置改变则停止。动态文案、作者资料仍保留 OCR 兜底，并保持返回原作品的严格校验。`recognitionTiming` 日志和证据 JSON 记录 `hierarchy` / `template` / `ocr` 来源及各次尝试耗时，不能将其与所属任务耗时重复相加。

控件为主、OCR 兜底（2026-11-11）：微信只在开启读屏类无障碍服务时才提供控件树，否则返回空节点。每个任务开始时，`collector/accessibility.py` 以 shell 身份临时开启 Google 无障碍套件中的「随选朗读」（`com.google.android.marvin.talkback/…SelectToSpeakService`），它不接管触摸；任务结束或失败时恢复原有设置。原设置先写入数据目录的 `accessibility-owner.json`，异常退出后由下一次任务恢复；用户自己开启的服务保持不变；未安装该套件时跳过，按原方式整页 OCR，日志 `controlsExposure` 记录状态。每次识别（`hierarchy.choose_snapshot`）按三层进行：
1. 控件文字：只读最上层（推荐流 `nsv`/`jlt` < 评论抽屉 `ean` < 其他面板，两台测试机的兄弟节点顺序不同，按层的类型判断）。文字保持控件原样；单行文字框收紧到文字高度，以便沿用按 OCR 版面写的解析器。图标名（头像、视频号logo、暂停、私信按钮等）不作为页面文字，只用于定位。
2. 容器局部 OCR：微信不提供文字的字段只有空容器（评论正文 `c6d`、回复展开 `kp7`、广告标签 `kr`、推荐流作者 `dzo`、主页昵称 `fzm`、认证 `fxa`、简介 `fy7`/`fy8`、关注/私信按钮 `fyk`/`mld`、消息回复按钮 `lz3`），对它们的外接区域做一次 OCR，只取落在容器内、且不与控件文字重复的结果。简介控件有文字时与 OCR 比较，保留更完整的一方。
3. 整页 OCR：该页面的解析检查（`CONTROL_PAGES`）不通过，或标签未登记，退回整页 OCR，并用位置重叠、文字相近的控件纠正错字（`correct_ocr`）。
2026-11-11 用两台手机 27 类页面的真机控件树和截图离线验证：15 类只用控件、10 类加一次局部 OCR、仅微信聊天列表退回整页 OCR；昵称、视频号 ID、评论者身份、消息全文和搜索卡片等字段不再依赖 OCR。控件 ID 随微信版本变化（如发送按钮在 8.0.79 为 `vzq`、8.0.80 为 `w4a`），按钮优先按文字匹配；容器 ID 失效时相应页面会退回整页 OCR。资料页「···」先按控件「设置」定位，找不到再用模板匹配；点赞、收藏、关注状态仍用取色或模板判断。

基础信息页面使用 8 秒就绪重试窗口（2026-11-08 由 5 秒放宽：vivo V2131A 正常约 2.7 秒就绪，曾连续超出原窗口），识别到标题和有效视频号 ID 立即继续。窗口含点击后的等待，不重复点击菜单；同步 OCR 无法中途取消，实际步骤耗时可能超过窗口。该版本需要重新打包，尚未真机验收，不能沿用旧版本耗时作为优化成绩。

该任务需要 profile 中的 Python Agent runtime，构建方式见根 README。手机使用前台模式并保持微信登录。运行日志包含各阶段的 `durationMs`、结果和 `runId`；失败阶段也记录耗时。返回文案确认重试属于校验子阶段，不能重复计入总时长。详细运行说明、数据位置和验收边界见 [第一批说明](../../docs/wechat-batch1.md)。

构建和宿主补丁说明见仓库根 README。原始截图、运行日志、APK 和开发机环境脚本不随仓库发布。截图回归工具保留在 `scripts/`，需自行提供 `captures/` 中的样本。

# 小红书行为进度清单

更新时间：2026-11-05

范围：手机端在小红书 App 内的采集、导航、互动与恢复行为。作品发布（图文笔记、视频笔记）不在需求范围内；发表评论、回复评论与私信仍保留。

字段、上传队列、ACK、数据库及 MediaCrawler 协同验收见[主任务清单](xiaohongshu-checklist.md)。本清单只记录手机行为验收，不以服务端联调作为勾选条件，也不与主清单相加计算完成率。

勾选表示该条行为已实现，并有覆盖所述场景的真机验收记录。单次局部跑通、代码接入或纯逻辑测试不等于完整行为验收；记录应注明日期、机型、应用版本、操作结果与失败场景。

## 已有局部验证

以下记录来自[插件状态](../plugins/xiaohongshu/status.json)，验证设备为 vivo V2131A / Android 12，日期为 2026-11-04：

- 图文单篇流程：发现页选作品 → 标题正文 → 作者主页小红书号 → 分享链接 → 返回列表 → 本地保存，采集约 24.6 秒，含准备共约 37 秒。
- 可见评论流程：读取 5 条评论 → 进入 1 位评论者主页 → 读取小红书号、粉丝数 → 返回原评论位置，操作约 17 秒，含准备共约 22.8 秒。
- 视频流程已有代码，尚未完成整体验收；现有验证仅覆盖只读采集，没有执行互动写操作。

## 2026-11-05 连续评论采集验证

设备：vivo V2131A / Android 12；小红书 9.52.1。使用手机上的 Python runtime 直接调用插件代码，未重新编译或安装 APK。

- 3 轮采集：9 条评论，含 5 条二级回复；展开 2 次，访问 3 位评论者并核对返回位置，约 73 秒。
- 默认上限验证：10 轮采集、20 条评论，含 10 条二级回复；展开 1 次，5 次主页往返涉及 4 名不同用户，约 141 秒。
- 补齐缺失父级与跨页重叠保护后的最终回归：3 轮、10 条评论（含 5 条回复）、2 次主页往返，约 46 秒。
- 本地报告的评论 key 无重复，二级回复均能关联本批一级评论，主页记录均能关联对应评论。三轮结束原因均为 `page_limit`，`complete=false`，没有宣称采完全部评论。
- 在手机 Python 上通过 12 项业务逻辑测试，覆盖跨页解析、重叠去重、回复归属、返回核对、停止/失败不提交和参数上限。
- 网络加载最多等待 90 秒；慢滑后等待两次一致的布局，丢失重叠评论或回复父级不明确时停止。该轮仅保留正文中的回复对象原文，后续进展见下一节。

## 2026-11-05 评论结束与折叠处理验证

设备及执行方式同上。新版代码仍未打入安装中的 APK。

- 从图文入口连续执行进入评论区、自动展开折叠评论和滚动到底：3 轮、5/5 条文本评论、展开折叠区 1 次，约 37 秒，`endReason=end_of_list`、`complete=true`。
- 零评论笔记：同时核对显示总数 0 和明确的空状态，约 11 秒，`endReason=empty_comments`、`complete=true`，未点击“抢首评”。
- 从长评论列表中途启动：读取 8/113 条后识别到底，约 43 秒，仍为 `complete=false`，不会把到达末尾等同于采齐。
- 实测发现时间栏带“翻译”入口会漏读评论，已修正；修复后上述 5 条全部采到。
- 回复对象新增 `replyToNickname`：仅提取二级回复正文中无歧义的“回复 昵称：”显示名，保留原文；多冒号、普通正文和空名字留空，不推断目标用户或评论 ID。
- 在手机 Python 回放上一批已核对的真实评论报告，正确提取 1 条回复对象显示名，保留原正文与父级关联；此项是历史报告回放，尚非新一轮 UI 端到端身份验收。
- 手机 Python 上通过 21 项业务逻辑测试，覆盖上述规则，以及折叠加载失败、假到底文案、截断到底标记、总数不一致和非空状态保护。

`complete` 只表示本轮文本评论条数与界面总数对齐，图片附件、用户身份补全和上传不在此声明内。大评论量、更多布局与网络变化仍需持续验收。

以下勾选仅代表注明设备上的行为验收；完整 APK 任务入口、多机型及服务端链路仍待验收。

## 图文采集与列表导航

- [ ] 通过可见卡片的实际边界选择作品，记录已处理卡片，连续处理时避免重复进入。
- [ ] 稳定识别图文详情，采集标题与正文，适配无独立标题的样式。
- [ ] 展开长正文并滚动补采，避免将截断文案误判为完整正文。
- [ ] 进入作者主页核对身份、读取小红书号，再返回原作品并核对标题/正文及作者。
- [ ] 从图文分享面板复制链接，读取对应作品的剪贴板内容并关闭面板。
- [ ] 完成一篇后返回瀑布流原位置，滚动并连续处理下一篇。

- [ ] 处理作者主页加载与身份校验，读取小红书号后返回原视频。
- [ ] 从视频右侧分享入口复制链接，关闭面板后核对仍为原视频。
- [ ] 完整跑通视频选帖、文案、作者、链接与返回列表，连续处理多篇不串作品。

- [ ] 点击展开二级回复并继续读取，保留所属一级评论及回复对象关系。（已验证展开与一级评论关联；已实现回复对象显示名提取，目标唯一身份仍未完成）

- [ ] 处理评论消失、主页不可访问、身份无法确认等情况，不记为采集成功，也不错误关联其他用户。

## 作品与评论互动

- [ ] 按配置点赞图文/视频，识别已有点赞状态并确认操作生效，避免重复点击取消点赞。
- [ ] 按配置收藏图文/视频，识别已有收藏状态并确认操作生效，避免重复点击取消收藏。
- [ ] 在目标作品发表一级评论，核对作品、输入内容与发送结果。
- [ ] 对目标评论点赞，确认对象和状态正确。
- [ ] 回复目标评论，核对回复对象、输入内容与发送结果。
- [ ] 接收指定作品和目标评论任务后定位并插队回复，完成后恢复原任务；无法定位时不误回复其他评论。

## 主页触达

- [ ] 按条件关注目标用户，识别已关注状态并确认生效。
- [ ] 打开目标用户主页首篇作品，按配置点赞/收藏后返回；空主页或不可访问时正确结束该动作。
- [ ] 进入目标用户私信会话，核对收件人、内容与发送结果，处理不可私信或发送受限状态。
- [ ] 记录实际完成的主页动作，返回原作品或评论位置后继续任务。

## 消息处理

- [ ] 巡检消息中心未读评论与 `@`，定位对应作品、评论及用户。
- [ ] 对可回复消息就地回复或点赞，核对目标和结果，避免重复处理同一消息。
- [ ] 消息处理结束后返回任务页面，失效或已删除内容不导致返回死循环。

## 搜索与运行模式

- [ ] 推荐模式连续选择、处理作品并滚动列表，跳过已处理卡片。
- [ ] 输入关键词搜索，并按配置选择综合、最新、最多评论或最多点赞排序。
- [ ] 按配置筛选笔记类型（不限/视频/图文）和发布时间，并确认筛选生效。
- [ ] 进入同城/附近并连续处理作品，识别入口或位置权限不可用的情况。
- [ ] 自动模式按配置切换推荐、搜索和同城阶段，切换后确认页面与阶段对应。

## 配额、异常与运行恢复

- [ ] 分别限制每日点赞、收藏、评论、关注、私信次数，达到配额后停止对应动作，重启不重置当日已用配额。
- [ ] 检测滑块或验证码后暂停，等待人工处理后核对页面再继续。
- [ ] 对加载失败、弹窗或意外页面执行有限次数的返回归位，无法恢复时停止并说明原因。
- [ ] 用户停止任务后不再继续点击或发送；恢复运行时重新识别页面和目标。
- [ ] 对已执行或结果不明确的互动先核对状态，避免恢复时重复评论、回复或私信。
- [ ] 验证连续多篇、多位评论者的运行与不同机型分辨率，记录失败与恢复结果。

## 实施顺序

1. 图文评论连续采集：翻页 → 展开回复 → 逐个访问评论者 → 返回原位置继续，同时补齐长正文与无独立标题适配。
2. 视频完整采集与视频评论抽屉。
3. 作品/评论互动、主页触达与消息处理；启用互动前完成对应配额、结果确认和停止保护。
4. 完整推荐、搜索、同城及自动模式，补齐连续运行与多机型验收。

返回归位、身份核对和停止保护随各阶段一起实现，不留到最后补做。

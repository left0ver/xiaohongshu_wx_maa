# 微信视频号清单：各批任务对应的页面操作

更新时间：2026-11-09

本文用大白话说明 [微信视频号上传与操作主任务清单](wechat-checklist.md) 里每一部分在手机微信页面上具体点哪里、怎么操作。代码依据是 `plugins/wechat/wechat_channels/collector/` 下的 `collection.py`、`comments.py`、`interactions.py`、`modes.py`。

## APK 入口现状（1.0.21）

| 清单部分 | 对应 APK 任务 | 能否在助手界面使用 |
| --- | --- | --- |
| 第一批 作品 | 采集当前视频（第一批） | 可以，只采当前一条 |
| 第二批 评论 | 采集作品及可见评论（第二批） | 可以，翻页、展开回复次数可在任务选项里设，默认 5 页、1 次，可勾「不限」 |
| 第三批 评论用户 | 同上，嵌在第二批任务里 | 可以，访问人数可在任务选项里设，默认 2 人，可勾「不限」 |
| 批量操作 | 互动当前视频（批量操作） | 资源 0.9.0 起可以（需重新打包，尚未真机验收）；插队回复暂不在界面上 |
| 模式接入 | `RunWechatMode` | 不能，界面暂无入口 |

各部分的「上报服务器、ACK、远端 SQL 验收」与页面操作无关，目前都未完成；所有结果只存在手机本地。

## 第一批 作品 VIDEO

一句话：刷到一条视频，把视频和作者的信息记下来，存到本地。对应 APK 任务「采集当前视频（第一批）」，代码 `collection.py:241-356`。

### ① 进到视频号推荐页（准备）

1. 打开微信
2. 点底部 **「发现」**
3. 点 **「视频号」**
4. 点顶部 **「推荐」** 标签，进入推荐流

如果一开始停在别的页面（作者主页、评论区、私信页、基础信息页等），会先按**返回键**退出来，最多试 7 步，不行就停止。

### ② 在推荐页认作者昵称（第 50 条）

5. **不点任何东西**，直接从当前视频画面左下角识别作者昵称，记下来。

### ③ 打开评论区，读文案、时间、地点（第 51 条）

6. 点右下角的 **评论按钮**（带评论数的那个图标），弹出评论区。
7. 读评论区**最上面的作品信息**：完整文案、发布时间、发布地点。
    - 作品信息被滑出了屏幕，就在评论区里**往下拉**把它拉回来，最多试 3 次。
    - 文案后面有「展开」，就**点「展开」**看全文，最多点 2 次。
8. 按**返回键**关掉评论区，回到视频。

### ④ 进作者主页，读资料（第 52 条）

9. 点左下角的 **作者昵称**，进入作者主页。
10. 读主页上的简介、认证信息、IP 属地、所在地。
    - 简介太长被折叠（有「展开」或「··」）时，**点开**再读一次。

### ⑤ 打开「更多信息」，读视频号 ID（第 53 条）

11. 点主页右上角的 **「…」**
12. 在弹出的菜单里点 **「更多信息」**
13. 等「基础信息」页面出来（最多等 8 秒，从点「更多信息」开始算），读里面的 **视频号 ID**。
14. 按**两次返回键**：先回作者主页，再回推荐页的那个视频。

### ⑥ 保存（第 54 条）

15. **不需要点页面**。用「昵称 + 文案」算出编号，生成伪链接，存到手机本地数据库 `videos.sqlite3`。以前采过的视频会覆盖原来那条，不重复存。

### 其余条目

- **第 55 条，连续上滑采多条**：采完一条后在屏幕上**往上滑**换下一条；遇到直播间、广告、已采过的视频，**不进去，直接再滑**。这个逻辑在「多模式运行」里（`modes.py`），**APK 的「采集当前视频」任务只采当前这一条**。
- **第 56–58 条，上报服务器、查数据库、验收**：跟手机页面没有关系，目前未完成。

## 第二批 评论 COMMENT

对应 APK 任务「采集作品及可见评论（第二批）」。这个任务会**先把第一批的整套操作做完**，再处理评论。代码 `comments.py:759-968`。

### ① 回到视频、打开评论区（准备）

1. 第一批做完时可能还停在作者主页、私信页或基础信息页，先按**返回键**，最多 2 次，退回视频画面。
2. 点右下角的**评论按钮**，弹出评论区（已经开着就跳过）。

### ② 读当前这一屏的评论（第 62、63、64 条）

3. **不点任何东西**，读这一屏每条评论的昵称、正文、时间和 IP 属地。
    - 「作者」「首评」「作者赞过」「置顶」等小标签、评论区广告、昵称旁的橙色蝴蝶图标都要过滤掉，不能当成昵称或正文。
4. 长评论末尾有「…展开」「全文」，就**点它**展开看全文，每屏最多点 2 次。

### ③ 展开二级回复（第 66 条）

5. 一级评论下面有「**展开 N 条回复**」或「**N条回复**」，就**点开**读回复，同时记下这条回复挂在哪条评论下面、回复的是谁。
    - 一组回复可能要点好几次（先「N条回复」，再「展开更多回复」），点到没有新回复为止；整个任务的点击次数受「最多展开回复次数」限制（默认 1）。
    - 点开后等约 1 秒再读，回复要等动画结束才显示。
    - 翻页后一屏开头只有回复、看不到它们挂的一级评论时，从前几屏已读到的同一条回复或上一条一级评论找回归属，不丢弃。

### ④ 点进评论者主页（属于第三批，夹在这里做）

6. 点评论者昵称进入主页，读资料后返回评论区。具体操作见下一节「第三批」。第 67 条要的「评论者 ID」就是从这一步拿回来填上的。

### ⑤ 往下翻页（第 65 条）

7. 在评论区里**往上滑**翻到下一屏，再从第 3 步开始重复。每次只滑可滑区域的一半，动作放慢（微信会带惯性多滑出约 1/4）。翻过去后如果和上一屏**没有一个相同的昵称**，说明滑过头漏了评论，就往回滑半屏重新读。
8. 什么时候停：
    - 出现「暂无评论」或「还没有评论」：空评论，算完整。
    - 滑了屏幕没变，或者看到底部：到底，算完整。
    - 采到的条数达到标题「评论 N」里的 N：算完整。
    - **翻满「最多翻页数」**（默认 5，勾「不限」则不限）还没到底：停下，记为「不完整」。
    - 翻页前如果评论者资料卡还开着，先关掉；否则滑不动会被误当成到底。

### ⑥ 关评论区、保存（第 68、69 条）

9. 按**返回键**关掉评论区，回到视频。
10. **不用操作页面**：评论存进本地数据库，每条都挂在第一批那条视频下面。同一条评论不会重复存；不同视频下内容相同的评论也不会被合并。

### 其余条目与注意

- 第 70–72 条（上报、ACK、数据库核对、验收）与页面无关，目前未完成。
- 资源 0.10.0 起任务有两个选项：「采集数量上限」三个输入框（最多翻页数，默认 5；最多展开回复次数，默认 1；最多访问评论者人数，默认 2，填 0 不访问），以及「不限数量」勾选框（勾上后三项都不限，翻到评论区底部、展开所有回复、访问每一位评论者）。评论多的视频在有上限时一般标为「不完整」（`complete=false`）。
- 每次读到的评论都会保留，展开回复后滚出屏幕的评论不会丢；被底部输入栏挡住的半条评论，下一屏读全后替换掉。

## 第三批 评论用户 USER

APK 里**没有单独的任务**，嵌在「采集作品及可见评论（第二批）」里执行。前提是评论区已打开、这一屏评论已读完。代码 `comments.py:532-618`。

### ① 选一个评论者

1. **不点页面**，先挑人：
    - 优先选**被别人回复过的人**，能补上二级回复里「回复的是谁」。
    - 其次选**昵称旁有橙色蝴蝶图标的人**（开了视频号，能拿到 ID）。
    - 昵称是纯表情的跳过。
2. 点之前再确认这条评论还在当前屏幕上，不在就跳过，记为「评论消失」。

### ② 点昵称进去（第 76、77 条）

3. 点这条评论的**昵称最左边那一两个字**。点在中间或右边容易点到时间、地区，弹出「回复」键盘。
4. 页面会出现以下情况：

**情况 A：对方开了视频号（页面上有「关注」和「私信」按钮）**

5. 读主页上的名字，**和评论昵称对一下**，对不上就返回、跳过，记为「身份无法确认」。
6. 读简介、认证、地区；简介被折叠就**点「展开」**再读。
7. 点右上角 **「…」** → **「更多信息」**，等「基础信息」页面出来（最多 8 秒），读**视频号 ID**。
8. 按**两次返回键**回到评论区。找不到「更多信息」也是按两次返回、跳过。

**情况 B：对方是普通微信用户（底部弹出一张小资料卡）**

5. 读资料卡上的昵称，和评论昵称对一下，再读地区或性别。
6. **ID 留空，不能编**，记为 `wechat-user-card`。
7. 按**一次返回键**关掉资料卡。

**两种都不是（没认出来、点进了别的页面）**：按返回键回到评论区（最多 2 次），跳过这个人。

### ③ 回到评论区并核对位置（第 80 条）

9. 确认回到了评论区：看得到「评论 N」，且不是停在主页或基础信息页；否则再按一次返回。
10. 检查**刚才那条评论还在不在屏幕上**，在就记 `returnVerified=true`，说明没串人、没串视频。
11. 再挑下一个人回到第 ① 步。访问人数受「最多访问评论者人数」限制（默认 2），跳过的人也计数；同一个人（昵称去掉截断的「...」后相同、地区不冲突）只访问一次。
    - 资料卡第一次返回没关上（动画中会吞掉返回键）时再按一次，最多 2 次。

### ④ 回填和保存（第 78、79 条，不用操作页面）

12. 把视频号 ID **填回这个人的评论**（`authorDouyinId`）。
13. 二级回复写着「回复 XXX」且 XXX 只对应一个人时，把 XXX 的 ID 填进那条回复的 `replyToDouyinId`；重名或认不准的**留空不猜**。
14. 每个评论者存成一条用户记录，挂在他那条评论下面，并记录触达状态：开了视频号的记 `visited`，普通微信用户记 `visited_no_channels_id`。
15. 同一个视频号 ID 只存一份；普通微信用户按「评论 + 昵称 + 地区」区分。
16. 被跳过的人记进 `skippedProfiles`，**不算采集成功，也不会挂到别人名下**。

### 其余条目与限制

- 第 81–83 条（上报、ACK、远端核对、验收）与页面无关，目前未完成。
- 默认每次任务**最多访问 2 个评论者**，所以大多数评论的 ID 还是空的；只有被访问过的人才能回填。需要全部回填时勾「不限数量」，耗时会明显变长。

## 批量操作（互动与触达）

对应清单第 87–92 条。这一批**不是采集，而是真的在微信里动手操作**，所以每一步都要防重复、防误操作。代码 `interactions.py`，入口 `InteractWechatWork`。清单里的勾是用开发脚本跑出来的；资源 0.9.0 起助手界面有了「互动当前视频（批量操作）」任务，见下面「助手界面怎么用」。

每个动作做不做由配置项决定（`interactions.py:1834`）。默认什么都不做，配了哪项就按下面的顺序执行哪项。和小红书不同，视频号是**按顺序全部判断一遍**，配了几项就依次做几项。

### 助手界面怎么用（资源 0.9.0）

在任务列表添加「互动当前视频（批量操作）」，默认不勾选、所有动作默认关闭。勾哪项做哪项：

| 界面选项 | 对应配置 | 说明 |
| --- | --- | --- |
| 作品操作：点赞视频 / 推荐·收藏 / 发一级评论 | `likeWork` / `collectWork` / `commentText` | 勾「发一级评论」后出现「评论内容」，必须填 |
| 评论区操作：给目标评论点赞 / 回复目标评论 / 访问目标评论者主页 | `likeComment` / `replyText` / `touchCommenterProfile` | 勾任一项后出现「目标评论」（昵称、内容关键词至少填一项）；回复还要填「回复内容」；访问主页可再勾关注、首作点赞、首作收藏 |
| 作者主页触达 | `touchAuthorProfile` | 打开后可勾关注、首作点赞、首作收藏，默认三项都勾 |
| 视频号消息巡检 | `inspectMessages` | 打开后可设是否点赞、最多处理条数（1–10，默认 1）、回复文字（留空只点赞） |
| 我的视频号昵称（可选） | `selfNickname` | 防止自己回复自己；留空时从评论区自动识别 |

与开发脚本的差别：

- 任务开始时先打开微信再进入视频号推荐页（`ensureFeed`），这时操作的可能是一条新视频。从助手界面启动时前台是助手，所以一定会先打开微信；微信已经停在推荐页时直接用当前这条，不会点「推荐」刷新。
- 勾了「发一级评论」「回复目标评论」却没填内容，输入框下方直接提示「请填写…」，点开始运行也**启动不了**（资源 0.11.0 起由宿主按输入项的 `verify` 拦截）。什么都没勾、评论区操作没填目标评论时，任务**直接失败，不碰手机**。目标为空会匹配到第一条评论，所以必须拦住。
- 各个动作**互不影响**：某个动作失败只记为 `failed`（附错误原因），按返回键退回推荐页后继续做后面的动作。认不出当前视频时，只有作品和评论区的动作记失败，作者主页触达和消息巡检照常做。只有点了「停止」或出现验证页才会中止整个任务。
- 运行记录 `runs/<id>/timings.jsonl` 最后一行 `interactionsCompleted` 带 `summary`，列出每个动作的结果（`performed`、`already_liked`、`target_not_found`、`failed` 等），有失败时另带 `failedActions`，任务也显示失败；完整结果始终写在同目录 `interactions.json`。
- 插队回复（`preemptiveReply`）需要同时指定视频和评论，本来是服务器下发用的，界面上暂不提供。

### ⓪ 动手之前（每次都做）

- 先识别当前页面。上次中断留下的键盘、基础信息页、菜单，先按**返回键**收起来。
- 每点一下之前检查**你是否在 App 里点了「停止」**，点了就立刻停手。

### ① 作品级互动（第 87 条）

**先认出是哪条视频**（每次都做，用于防重复）

1. 必须停在推荐页的视频画面上。读左下角**作者昵称**和上方的**文案**。
2. 文案的位置有时被微信换成「热评」，这时**打开评论区**，读最上面作品信息里的文案，读完关掉。
3. 和本地记录里见过的视频比：作者对得上、文案相似度达到 80%（OCR 可能读错几个字；推荐页上的文案被截断时，只和完整文案的开头比），就当成同一条视频。
4. 不在推荐页、读不到作者（比如一开始就停在评论区）时，**直接报错停下**，不点赞、不评论、不回复。

**点赞视频**（`likeWork`）

1. 停在评论区、主页等页面时，先按返回键退回视频画面，最多 3 次。
2. 看右下角**拇指**：已经是红色，或本地记录里赞过，就**不点**，记「已赞过」（防止再点变成取消）。
3. 没赞过就先检查今天的点赞次数（默认每天 50 次），然后**点一下拇指**。
4. 点完确认拇指变红或点赞数加 1，否则报错停下。

**推荐 / 收藏**（`collectWork`）：和点赞一样，点的是**红心**，默认每天 30 次。

**发一级评论**（`commentText`）

1. 查本地记录，这条视频发过同样的话就跳过。
2. 点右下角**评论按钮**打开评论区。
3. 点底部 **「发表评论」输入框**。
4. **粘贴**评论文字。
5. 点 **「发送」**。
6. 核对评论区出现了这条评论，或评论数加 1。
7. 记下「这条是我自己发的」，用于防止后面回复自己。默认每天最多 20 条。

### ② 评论区触达（第 88 条）

**给某条评论点赞**（`likeComment`）

1. 打开评论区，**往上滑翻页**找目标评论（按昵称或内容），最多 10 页，翻页方式同第二批。
2. 找不到就报「没找到」，**不会随便点一条**。
3. 找到后看评论右边的小拇指：赞过就跳过；没赞就**点一下**，确认变红或赞数加 1。

**回复某条评论**（`replyText`）

1. 同样先翻页找到目标评论。
2. **先看回复过没有**，满足任一就跳过：
    - 本地记录里，同一条视频、昵称对得上、评论内容相似度达到 80% 的评论，已经回复过同样的话；
    - 这条评论所在的楼里，已经能看到自己发的同样的回复。
3. **再确认不是自己发的**，三层判断满足任一就**不回复**：
    - 评论地区位置显示「我」，或昵称就是自己；
    - 本地记录里标过「这是我发的」；
    - 点了之后**没弹出「回复 XXX:」输入框**（微信对自己的评论不弹）。**已知问题**：评论开头是蓝色高亮的搜索词时，点下去弹出的是底部搜索条，也没有回复框，会被误判成自己的评论。
4. **点这条评论的正文**，弹出「回复 XXX:」输入框。
5. 粘贴回复内容，点 **「发送」**，确认评论下面出现了这条回复。

### ③ 插队回复（第 89 条）

配置项 `preemptiveReply`：给定一个指定视频和指定评论（比如服务器挑出的高意向评论），让手机去回复。

1. 看当前视频是不是目标视频（打开评论区对作者和文案）。
2. 不是就在推荐页**往上滑**换下一条，最多滑 2 次。
3. 找到后打开评论区找目标评论，按 ② 的流程回复。
4. 回复完**往回滑**回到原来那条视频，继续原来的事（`restoredToOriginalTask`）。
5. 视频或评论找不到就**直接放弃**，不回复别的，同样滑回去。

### ④ 主页触达（第 90 条）

**作者主页**（`touchAuthorProfile`）

1. 在视频画面点左下角**作者昵称**进入主页。
2. **关注**：显示「已关注」就不点（再点会取关）；显示「关注」就点，确认变成「已关注」。默认每天 20 次。
3. **主页第一个视频点赞 / 收藏**：在作品格子里**点第一个视频**，按 ① 的方法点赞、点红心，按**返回键**回主页。主页没有视频就跳过。
4. **私信：不做**，目前故意跳过（`dmSkipped`）。
5. 按返回键回到视频画面，并确认回到了推荐页。

**评论者主页**（`touchCommenterProfile`）

- 在评论区找到这个人，**点他的昵称**进入主页，做法同上：关注、第一个视频点赞和收藏。
- 做完按返回键回到评论区，核对**原来那条评论还在原位**。
- 对方只是普通微信用户（只弹资料卡）就只记「看过，没有视频号」，不做任何操作。

每次都会记录实际做了哪些动作（关注、首作点赞、首作收藏），触达状态记为「已触达」或「只看过」。

### ⑤ 消息通知巡检与回复（第 91 条）

配置项 `inspectMessages`。

1. 在视频号推荐页点右上角**个人头像**，进入「个人页」。
2. 点 **「视频号消息」**，再点上面的 **「评论」** 标签。注意不是「消息」：「消息」是以观众身份收到的消息，没有文字标签；只有找不到「视频号消息」时才退回「消息」。
3. 读通知列表：谁、评论了什么、什么时候。
4. 对没处理过的通知：
    - 点通知旁的**小拇指**给对方评论点赞，确认变红；
    - 点 **「回复」**，粘贴内容，点 **「发送」**。
5. 每处理一条就记下来，下次不重复。默认一次只处理 1 条。
6. 处理完一直按**返回键**（最多 4 次），直到回到视频号推荐页。

### ⑥ 每日配额（第 92 条）

不在页面上操作，是一个总限制：

- 每天上限：**点赞 50、推荐/收藏 30、评论 20、关注 20、私信 10**。
- 次数用完后对应操作直接拦住。
- 已用次数存在 `daily_quotas.json`，**重启或重开任务不清零**，第二天才清零。
- 「这条是我自己发的」记录跨天保留，继续防止回复自己。

## 模式接入

对应清单第 96–99 条。解决的是**去哪里找视频**：从推荐、朋友、关注、同城、搜索等入口刷视频，**每刷到一条就套用前面几批的操作**。代码 `modes.py`，入口 `RunWechatMode`，**APK 界面暂无入口**。不指定模式时默认跑推荐模式、采 2 条。

### 所有模式通用：刷到一条视频后做什么

1. **先看这一屏是不是正常视频**，以下情况**不点进去，直接往上滑**：
    - 有「直播中」「点击进入直播间」字样的直播预览；
    - 已经误进直播间（底部有「说点什么」，或有「在线观众」）；
    - 广告（带「广告」「了解详情」「立即下载」「立即购买」等）。
2. **再看是不是采过的**：拿作者名和文案开头对 `seen.json`，采过就**往上滑**跳过。
3. **新视频才处理**，按配置可做三件事：
    - 采集视频（第一批那套），默认开启；
    - 采评论（第二、三批那套），默认关闭；
    - 互动（批量操作那套），默认关闭。
4. 处理完记入已读，然后**往上滑**换下一条。
5. 刷够条数就停；**最多滑 8 次**，滑完没凑够也停。

两道保护：

- **出现验证码或滑块**（「安全验证」「拖动滑块」「操作过于频繁」等）：**一下都不点**，原地暂停，等人工处理完、页面恢复正常再继续。
- **页面跑偏**（加载失败、弹窗、进了别的页面）：最多按 4 次返回键回到原入口；回不去就停止并写明原因。

### 第 96 条：推荐模式

1. 进入视频号（发现 → 视频号）。
2. 点顶部 **「推荐」**，并确认被选中（字变黑加粗）。
3. 按「通用流程」一条条刷。

### 第 97 条：搜索模式

1. 在视频号页面点右上角**放大镜（搜索）**。
2. 点搜索框，**粘贴关键词**（默认「脱口秀」），点右边 **「搜索」**。
3. 确认进入搜索结果页；有「视频」标签就**点「视频」**。
4. **设置筛选条件**，微信有两种界面：
    - **直接显示筛选条件**：点排序（**不限 / 最新 / 最热**）；点时长，在弹出框选 **不限 / 5分钟以下 / 5–20分钟 / 20分钟以上**；点范围，选 **不限 / 已关注 / 最近看过**。
    - **收在「筛选」按钮里**：点右上 **「筛选」**，在面板里依次选「排序」「范围」「时长」，最后点「收起」。
5. 在搜索结果里**找一个没采过的视频卡片**，这一屏没有就往下滑，最多 5 屏。
6. **点开这个视频**，按「通用流程」处理。
7. 按**返回键**回到搜索结果，确认**回到了原来的列表**（`returnedToSearchResults`）。
8. 接着找下一个，直到采够条数。

注意：搜索结果是一格格卡片，所以是**点开一条、返回、再点下一条**，不是在视频里往上滑。

### 第 98 条：朋友 / 关注 / 同城模式

1. 进入视频号。
2. 点顶部对应标签：**「朋友」**、**「关注」**或 **「同城」**（也可能叫「附近」）。
    - 顶部找不到这个标签，就记为「入口不可用」（`entry_unavailable`），**安全结束，不乱点**。有些账号没有「同城」。
3. 弹出 **「开启定位权限」** 之类的弹窗，自动点 **「暂时不了」**、「取消」、「拒绝」或「以后再说」关掉。
    - 也可配置成同城**必须有定位权限**，没有就直接停。
4. 确认标签被选中，然后按「通用流程」往上滑着刷。

### 第 99 条：自动模式

把上面几种模式**排好顺序，一个接一个跑**：

1. 按顺序进入每个阶段。默认是：
    - **推荐**采 1 条
    - **朋友**采 1 条
    - **搜索**「脱口秀」，排序最新，时长 5 分钟以下，采 1 条

    顺序可配置，例如清单实测跑的是「朋友 → 关注 → 同城 → 推荐 → 搜索」5 个阶段。
2. **每次切换后核对**确实到了目标页面（比如顶部「关注」真的被选中），才开始刷，结果记为 `stageSwitchVerified`。
3. 一个阶段结束后先按返回键回推荐页，再进入下一阶段。
4. 可以在最后加一个**消息巡检**阶段，做法同批量操作第 ⑤ 步。
5. 每条采到的视频都标上**来源**，如 `AUTO_RECOMMEND`、`AUTO_FRIENDS`、`AUTO_SEARCH`。

### 一句话总结

**各模式只是入口不一样**：推荐、朋友、关注、同城是点顶部标签后上滑刷；搜索是输关键词、设筛选、点卡片再返回。**进到具体视频之后做的事都一样**，就是第一到第三批的采集，加上可选的互动。
